# 周复盘（weekly-review）

> 用途：保研冲刺期时间紧，用一条命令把一周的工作量自动汇总成**表格 + 要点**的周报，不写长段落，一眼看全进度与卡点。

## 适用场景

- 每周日/周一固定复盘，向导师或自己交代进度
- 保研面试前整理“这学期我做了啥”的素材
- 配合 `git-ship` 看本周提交，配合 `techdebt` 看本周清了多少债

## 执行步骤

### 1. 拉取本周 git 提交（按当前作者）

在仓库根目录打开 Git Bash：

```bash
git log --since="1 week ago" --pretty=format:"%ad|%s" --date=short \
   --author="$(git config user.name)"
```

想看改动文件量，加 `--stat`：

```bash
git log --since="1 week ago" --stat --author="$(git config user.name)"
```

### 2. 读取每日记忆日志（若存在）

日志目录在 `D:\.workbuddy\memory\`，优先读本周（周一至今）的文件：

```bash
ls -1 /d/.workbuddy/memory/ 2>/dev/null | grep -E "$(date +%Y-%m)-[0-9]{2}" 
```

把列出的每个日志文件用 Read 工具打开，提取“今天完成 / 卡住 / 明天计划”要点。

> 若该目录不存在或为空，跳过此步，仅基于 git 记录复盘，并在周报注明“无记忆日志”。

### 3. 归类

把步骤 1、2 的信息分到四类：本周完成、未完成、卡点、下周计划。git 提交对应“完成”；记忆日志里的“卡住”对应“卡点”；“明天计划 / 待办”对应“下周计划”。

## 输出格式

输出严格用表格和要点，不要长段落。模板如下：

### 周复盘 · 2026-09-07 ~ 2026-09-13

**一、本周完成**

| 日期 | 事项 | 关联提交/日志 |
|---|---|---|
| 09-09 | 微信小程序登录页联调 | `feat: 登录页 wx.login 联调` |
| 09-11 | 作品集 README 重写 | 记忆日志 09-11 |

**二、未完成**

- [ ] 后端接口鉴权（预计还需 1 天）
- [ ] 作品集部署到云服务器

**三、卡点**

- 小程序 `wx.request` 真机调试 HTTPS 证书校验失败，待申请域名备案
- numpy 版本与导师环境不一致，已在记忆日志记录

**四、下周计划**

- [ ] 完成接口鉴权并补测试
- [ ] 把 3 个作品部署上线，写部署文档
- [ ] 跑一次 `techdebt` 清作品集旧债

## 注意事项

1. 时间范围默认“最近 7 天”；若用户指定了起止日期，改用 `--since="YYYY-MM-DD" --until="YYYY-MM-DD"`。
2. 多仓库场景：对每个仓库分别跑步骤 1，再合并到同一张“完成”表。
3. 卡点要写**具体阻碍 + 已尝试的解决**，方便下周直接接着干，而不是重复踩坑。
4. 周报里出现的提交 hash 用反引号包裹，便于跳转。
5. 不要编造没发生的事；git 没有提交、记忆日志没有记录的，就归入“未完成/下周计划”，不要硬凑“完成”。
