# 多级退回机制

> 每个功能点必须设计**至少 2 套备选方案**（Plan A → Plan B → Plan C）。

---

## 设计原则

| 方案 | 定位 | 触发条件 |
|------|------|------------|
| **Plan A** | 推荐方案（最优） | 优先尝试 |
| **Plan B** | 备选方案（次优） | Plan A 失败 → 自动降级 |
| **Plan C** | 兜底方案（保底） | Plan B 失败 → 自动降级 |

**触发条件**：某个方案执行失败 → 自动尝试下一个方案，**不询问用户**（除非所有方案都失败）。

---

## SKILL.md 中的写法

```markdown
## 功能：XXX

### Plan A（推荐方案）
- 工具：XXX
- 前提：需要 XXX 已安装
- 执行：
```bash
xxx --option value
```
- 如果失败 → 自动降级到 Plan B

### Plan B（备选方案）
- 工具：YYY
- 前提：需要 YYY 已安装 或 使用内置工具
- 执行：
```bash
yyy --alternate
```
- 如果失败 → 自动降级到 Plan C

### Plan C（兜底方案）
- 工具：ZZZ（或提示用户手动操作）
- 执行：
```bash
# 兜底命令
```
- 一定会成功，或给出明确的手动操作步骤
```

---

## 示例：网页抓取多级退回

```markdown
### 二级：网页抓取

**Plan A（推荐）**：
```bash
playwright-cli open https://example.com
playwright-cli snapshot
```
- 前提：`playwright-cli` 已安装
- 适用：JS 渲染、SPA

**Plan B（备选）**：
```bash
curl -s https://example.com | python -c "import sys; from bs4 import BeautifulSoup; soup=BeautifulSoup(sys.stdin.read(), 'html.parser'); print(soup.get_text())"
```
- 前提：`requests`、`beautifulsoup4` 已安装
- 适用：静态 HTML

**Plan C（兜底）**：
```bash
# 使用 WebFetch 工具
```
- 适用：所有场景，无需安装额外工具
```

## 自动降级实现

WorkBuddy 会自动按顺序尝试：

1. 执行 Plan A 命令
2. 如果报错/超时 → 自动执行 Plan B
3. 如果还是失败 → 自动执行 Plan C
4. 如果全部失败 → 报告用户，提供手动步骤

**无需用户干预**，自动完成降级。

---

## 多级退回检查清单

| 检查项 | 说明 |
|---------|------|
| 每个功能点都有 Plan B 吗？ | 必须 |
| Plan B 失败时自动降级到 Plan C 吗？ | 必须 |
| 所有方案都失败时给出明确手动步骤吗？ | 必须 |
| 触发条件是自动的吗（不询问用户）？ | 必须 |
