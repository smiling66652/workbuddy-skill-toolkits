# 常见问题

> 整合 skills 过程中常见问题及解决方案。

---

## Q1：整合后的 skill 太大怎么办？

**A**：拆到 `references/` 下，SKILL.md 只保留核心逻辑（≤ 5000 词）。

**示例**：
```
skill-name/
├── SKILL.md（主文件，≤ 5000 词）
└── references/
    ├── 工具A.md（详细用法）
    ├── 工具B.md（详细用法）
    └── 工具C.md（详细用法）
```

---

## Q2：如何判断哪些 skills 需要整合？

**A**：按功能分类，同一功能类别的 skills 都需要整合。

**示例**：
- 所有"网页抓取"相关的 skills → 整合为 `联网工具箱`
- 所有"PDF 处理"相关的 skills → 整合为 `文档工具箱`
- 所有"微信小程序"相关的 skills → 整合为 `微信小程序开发套件`

---

## Q3：整合后旧 skills 可以恢复吗？

**A**：可以。归档在 `.archived/` 目录下，随时可以移回来。

**操作**：
```bash
# 恢复已归档的 skill
mv "C:/Users/Matebook/.workbuddy/skills/.archived/old-skill-A" "C:/Users/Matebook/.workbuddy/skills/"
```

---

## Q4：如何搜索同类最佳工具？

**A**：使用 `联网工具箱` skill，搜索关键词：
- `best CLI tool for X 2025`
- `X vs Y comparison`
- `awesome-X`（GitHub 上的精选列表）

---

## Q5：多级退回机制如何实现？

**A**：在 SKILL.md 的每个功能点中，明确写出 Plan A/B/C 的命令和判断条件。

**示例**：
```markdown
### 二级：网页抓取

**Plan A（推荐）**：
```bash
playwright-cli open https://example.com
playwright-cli snapshot
```
- 前提：`playwright-cli` 已安装
- 适用：JS 渲染、SPA

**Plan B（备选）**：
```bash
curl -s https://example.com | python -c "import sys; from bs4 import BeautifulSoup; soup=BeautifulSoup(sys.stdin.read(), 'html.parser'); print(soup.get_text())"
```
- 前提：`requests`、`beautifulsoup4` 已安装
- 适用：静态 HTML

**Plan C（兜底）**：
```bash
# 使用 WebFetch 工具
```
- 适用：所有场景，无需安装额外工具
```

WorkBuddy 会自动按顺序尝试。

---

## Q6：references/ 目录下的文件如何组织？

**A**：每个工具的详细用法、API 文档、示例拆到 `references/` 下。

**命名规范**：
- `references/工具名.md`
- 例如：`references/Playwright-CLI.md`、`references/Agent-Browser.md`

**内容规范**：
- 每个文件 ≤ 4000 字符
- 包含：安装方法、使用示例、注意事项、故障排查

---

## Q7：如何确保整合后的 skill 比原有的更强？

**A**：遵循"横向对比，集众家之所长"原则。

**步骤**：
1. 全量扫描：找出所有同类 skills
2. 横向对比：制作对比表，列出每个工具的优缺点
3. 取最长板：每个功能点取所有 skills 中最优的实现方式
4. 补齐短板：某个功能所有现有 skills 都做得不好 → 联网搜索更好的工具
5. 多级退回：每个功能点设计至少 2 套备选方案

---

## Q8：整合后的 skill 如何测试验证？

**A**：必须测试以下四项：

1. **触发测试**：说一句话，确认 skill 被正确触发
2. **功能测试**：测试每个二级功能是否正常工作
3. **退回测试**：故意让 Plan A 失败，确认自动降级到 Plan B
4. **边界测试**：测试用户可能的异常输入

**输出**：在 `references/test-report.md` 中记录测试结果。

---

## Q9：如何在 SKILL.md 中写预设期待命中？

**A**：预先定义用户可能的期待，当用户输入匹配时直接命中。

**示例**：
```markdown
## 预设期待命中

| 用户输入模式 | 直接命中 | 说明 |
|-------------|------------|------|
| "搜索 XXX" | 一级→搜索需求 → 二级→智能搜索 → 三级→执行 | 无需询问 |
| "抓取这个页面" | 一级→抓取需求 → 二级→网页抓取 → 三级→执行 | 自动选择最优方法 |
| "打开浏览器点击XXX" | 一级→自动化需求 → 二级→Playwright → 三级→执行 | 支持登录态 |
```

**效果**：用户感觉"它懂我"，不需要反复解释。

---

## Q10：整合 skill 时，如何避免遗漏？

**A**：遵循"全量扫描，不遗漏"原则。

**步骤**：
1. 按名称搜索：`ls ~/.workbuddy/skills/ | grep -i "关键词"`
2. 按内容搜索：`find ~/.workbuddy/skills/ -name "SKILL.md" | xargs grep -l "关键词"`
3. 检查 archived：`ls ~/.workbuddy/skills/.archived/`（如果之前整合过）
4. 联网搜索：是否有更好的同类 skill 可以下载

**输出**：在 SKILL.md 的"整合来源"章节，列出所有被替代的旧 skills 名称。
