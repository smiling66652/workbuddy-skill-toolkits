# 二级：内容总结

**适用场景**：用户需要总结文章、视频、音频、PDF

> **核心认知：总结这件事本身不需要任何 CLI。**
> 你（Agent）就是总结器。这一层真正要解决的问题是**把内容拿到手**——拿内容属于抓取层的事。

---

## 正确的心智模型

```
① 拿内容  →  按内容类型分派到对应的层（见下表）
② 总结    →  直接由你完成，不要绕道调第三方 summarize 工具
```

**为什么不要用第三方 summarize CLI**：它做的事就是「抓取 + 调一次 LLM」，而你两样都有。
额外装一个 CLI 只会引入新的失败点（要 key、要联网、格式转换损耗），并且**多一次内容外传**。

---

## ① 拿内容：按类型分派

| 内容类型 | 怎么做 | 详见 |
|---|---|---|
| 网页文章 | `curl` 看 HTML 有没有正文 → 有则 Jina，无则 CDP 直连 | [智能搜索](智能搜索.md) |
| 需要登录的页面 | CDP 直连（继承登录态） | [CDP浏览器直连](CDP浏览器直连.md) |
| JS 渲染 / SPA 页面 | CDP 直连，或 `node scripts/pw.mjs` | [网页抓取](网页抓取.md) |
| PDF / Word / PPT / Excel | 本地文件直接读；在线文件先 `curl -O` 下载再读 | [文档工具箱](../../文档工具箱/SKILL.md) |
| 图片（含文字） | OCR 识别后总结 | 图像处理技能包 |
| YouTube 视频 | 抓字幕，别下视频 | [YouTube转录](YouTube转录.md) |
| 音频文件 | 转写后总结 | 见下 |
| 公众号 / 小红书等 | CDP 直连（静态层被反爬限制） | [CDP浏览器直连](CDP浏览器直连.md) |

**判断顺序永远是**：先看静态层能不能拿到 → 拿不到再上浏览器。别一上来就开浏览器。

---

## ② 总结：直接做

拿到正文后直接总结。几个要点：

- **长内容先分块再汇总**，别试图一次塞进上下文然后指望不丢细节
- **明确总结目标**：是要「讲了什么」的概览，还是要「和我问题相关的部分」？后者更该做定向提取而非全篇摘要
- **保留可核验信息**：原文链接、作者、日期、关键数字——总结丢掉了出处就没法验证
- **区分事实与观点**：原文的说法 vs 你的推断，别混成一段

## 关于本机未配置的可选工具

| 工具 | 状态 | 说明 |
|---|---|---|
| `summarize`（PyPI） | ❌ 未装 | 包确实存在，但**如上所述没必要装** |
| MiniMax CLI `mmx` | ❌ 未装 | 见 [AI生成](AI生成.md)，仅生成任务需要 |
| `youtube-transcript-api` | ❌ 未装 | 需要抓 YouTube 字幕时再装 |
| OCR（rapidocr 等） | 见图像处理技能包 | 本技能包不负责 |

**不要因为表里写着就以为它们能用**——跑 `node scripts/doctor.mjs` 看实测结果。

## 故障排查

| 问题 | 解决方案 |
|------|-----------|
| 抓不到正文 | 先 `curl` 判断是否为 JS 渲染；是则上 CDP 直连 |
| 内容被付费墙遮住 | 见 `付费文档下载.md` |
| 内容太长 | 先分块处理，或只提取与问题相关的章节 |
| 总结结果不准确 | 提供更明确的总结目标，或先核对原文关键段落 |
| 视频没字幕 | 见 [YouTube转录](YouTube转录.md) |
