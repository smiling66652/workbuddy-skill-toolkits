# 二级：智能搜索

**适用场景**：用户需要搜索信息、查资料、找最新进展

> 搜索引擎和聚合平台是**发现**工具，不是**证明**工具。核实必须回到一手来源。

## 分层升级路径

从最轻的一层开始，拿不到再升级：

| 层 | 手段 | 何时用 |
|----|------|--------|
| **L0** | WebSearch | 发现线索、定位来源 |
| **L0** | WebFetch / curl | URL 已知，定向提取；curl 拿原始 HTML（meta、JSON-LD） |
| **L0.5** | **Jina** | 正文为核心的页面，省 token |
| **L1** | **CDP 直连** | 需要登录态、静态层被反爬拦截、需要交互 |

**升级判据**：目标站点你已在本机浏览器登录过，或已知静态层对该平台无效（小红书、微信公众号等）→ 直接上 L1，别在 L0 反复重试。

## 三级执行

```bash
# L0：WebSearch（优先）
# 调用 WebSearch 工具，中英文引擎自动选择

# L0：WebFetch 抓取搜索结果页，高级语法
# site:github.com react      # 站内搜索
# filetype:pdf 报告        # 指定文件类型
# "机器学习"                # 精确匹配
# -time:h  AI新闻          # 过去1小时

# L0：curl 拿原始 HTML（meta / JSON-LD 结构化字段）
curl -sL "https://example.com" | grep -o '<meta[^>]*>'
```

## L0.5：Jina 预处理层

把网页转成 Markdown，大幅节省 token。

```bash
# 用法：URL 前加前缀，且不带 http://
curl -s "https://r.jina.ai/example.com"
```

> ⚠️ **本机当前不可达（2026-09-11 实测）**
> `r.jina.ai` 直连与 `--socks5-hostname 127.0.0.1:10808` 走代理**均返回 000**，而对照组 `example.com` 直连 200。
> 也就是说 **L0.5 这一层在本机是死的**，不要把它作为默认路径。
>
> **替代方案（本机可用）**：
> 1. **WebFetch** —— Agent 内置，URL 已知时直接定向提取，零配置
> 2. **curl + 本地正文提取** —— `trafilatura`（装：`venv_python -m pip install trafilatura`）
> 3. **CDP 直连** —— 前两条都不行时

| 项 | 说明 |
|----|------|
| 限流 | 无 key → 20 RPM；有免费 key → 500 RPM 且注册送 1000 万 token |
| **适合** | 文章、博客、文档、PDF 等**正文已存在于 HTML 里**的页面 |
| ⚠️ **硬限制** | **不执行 JavaScript**（架构性限制，非 bug）→ SPA / React / Vue / Next.js 客户端渲染页、Notion 托管文档、Shopify 商品页会返回**只有导航和页脚、没有正文**的 Markdown |
| 其他限制 | 不绕反爬，被拦就报错；搜索端点 `s.jina.ai` 只返回前 5 条全文，不可配置 |
| 计费 | 按 token 计 → 页面长短导致成本波动 10 倍以上 |
| 注意 | 已被 Elastic 收购，官方承诺继续维护 Reader |

> **实践判据**：`curl` 一眼看不出正文（只有 `<div id="app"></div>`）→ 别用 Jina，直接上 L1 CDP 直连。
> 判断顺序永远是「先 curl 看 HTML 里有没有正文」→ 有则提取，无则上浏览器。

> 需要**批量搜索 / 结构化 SERP / 语义检索**时，见 [搜索层 API 选型](AI搜索.md)。

## L1：本地浏览器资源检索

用户指向**本人访问过的页面**（"我之前看的那个讲 X 的文章"）或**组织内部系统**（"我们的 XX 平台"，公网搜不到）时：

```bash
node "C:/Users/Matebook/.workbuddy/skills/联网工具箱/scripts/find-url.mjs" [关键词...] \
  [--only bookmarks|history] [--browser chrome|edge] [--limit N] \
  [--since 1d|7h|YYYY-MM-DD] [--sort recent|visits]
```

| 参数 | 说明 |
|------|------|
| 关键词 | 空格分词、多词 AND，匹配 title + url；可省略 |
| `--browser` | 限定 chrome / edge；默认遍历所有已装 Chromium 系浏览器 |
| `--only` | 只搜书签或只搜历史 |
| `--since` / `--sort` | 仅作用于历史 |
| `--sort visits` | 按访问次数排序（适合"高频访问的网站"） |

**典型流程**：`find-url` 拿到 URL → CDP 打开（已登录态直达）→ `/eval` 提取内容。

## 信息核实：一手来源对照

核实的目标是**一手来源**，而非更多二手报道——多个媒体引用同一个错误会造成循环印证假象。

| 信息类型 | 一手来源 |
|----------|---------|
| 政策/法规 | 发布机构官网 |
| 企业公告 | 公司官方新闻页 |
| 学术声明 | 原始论文/机构官网 |
| 工具能力/用法 | 官方文档、源码 |

找不到官网时，权威媒体的**原创报道**（非转载）可作次级依据，但需向用户说明："未找到官方原文，以下核实来自[媒体名]报道，存在转述误差可能。"单一来源时同样声明。

## 工具对比

| 工具 | 速度 | 精度 | 适用场景 |
|------|------|------|------------|
| WebSearch | 快 | 高 | 通用搜索（**默认首选**） |
| WebFetch | 中 | 中 | URL 已知，定向提取 |
| curl | 快 | 高 | 原始 HTML / 结构化字段（先用它判断有没有正文） |
| Jina | 中 | 中 | 正文已在 HTML 里的页面，省 token |
| CDP 直连 | 中 | **高** | 登录态、反爬、JS 渲染、交互 |
| scripts/pw.mjs | 中 | 高 | CDP 不可用时的本地浏览器执行器（零安装） |

需要**搜索 API**（Tavily / Exa / Serper / Brave / Firecrawl）时见 [搜索层 API 选型](AI搜索.md)。

## 并行调研

多个**独立**目标时，分治给子 Agent 并行：总耗时 ≈ 单个子任务时长，且抓取内容不进主 Agent 上下文。

> ⚠️ **不要在并发子 Agent 间驱动同一个标签页**。不同 targetId 之间无竞态，但同一页并发操作会互相干扰导航、页面状态与网络拦截，也更容易触发风控。

子 Agent prompt 必须写 `必须加载「联网工具箱」skill 并遵循指引`。**描述目标，不指定步骤**——避免「搜索xx」这类暗示手段的动词把子 Agent 锚定到 WebSearch。

## 故障排查

| 问题 | 解决方案 |
|------|-----------|
| WebSearch 无结果 | 更换关键词，或改用 WebFetch / curl |
| 多次搜索无质的改进 | **升级到一手来源**（官网、官方平台、原始页面），不要在搜索上打转 |
| 页面需要登录 | 升级到 CDP 直连 |
| Jina 返回的 Markdown 只有导航和页脚 | 该页是 JS 渲染，Jina 拿不到正文 → 上 CDP 直连 |
| 返回 403 / Cloudflare 挑战页 | 见 [反爬对抗](反爬对抗.md) |
| 搜索结果不准确 | 使用高级语法缩小范围 |
| 需要批量/结构化搜索 | 见 [搜索层 API 选型](AI搜索.md) |
