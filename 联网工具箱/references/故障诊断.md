# 故障诊断

**何时读**：任何一层报错、看起来「环境坏了」、命令没输出、进程假死时。
本页按**症状**组织，不按工具组织——拿着实际报错来对照，比按固定脚本排查快得多。

> **第一原则**：不要照文档盲猜，先问环境。
> ```bash
> node scripts/doctor.mjs          # 人读能力矩阵
> node scripts/doctor.mjs --json   # 机器可读
> node scripts/doctor.mjs --quick  # 跳过联网探测，最快
> ```

## 0. Node 运行时（一切的地基）

```bash
node -e "console.log('ok')"
```

**必须打印 `ok`**。没打印（SIGILL / exit 133 / 崩溃）说明 PATH 上的 node 坏了。

⚠️ **`node --version` 通过不算数**——只打印版本号不执行代码。`agent-browser` 内部会 spawn Node 子进程，
那个 Node 坏了会 `Daemon process exited during startup with no error output`，即使 `agent-browser --version` 看起来正常。
同理 `file /path/to/node` 显示架构正确也不能证明它能跑。

**救急**（只对本次命令覆盖 PATH）：

```bash
PATH="/path/to/working-node/bin:$PATH" agent-browser open <url>
```

**本机正解**：统一用托管 Node

```
C:/Users/Matebook/.workbuddy/binaries/node/versions/22.22.2-3/node.exe
```

> SKILL.md 要求 Node 22+（CDP Proxy 用原生 WebSocket）。

## 1. agent-browser

两条规则解释绝大多数故障：

- **前置条件**：`node -e` 检查必须过
- **执行原则**：只用它自己的安装渠道，**不要并行跑 `npx playwright install`**

| 症状 | 违反了哪条 | 处理 |
|---|---|---|
| Exit 133 / SIGILL / Illegal instruction | 前置条件（Node 坏了） | 跑 Node 检查；必要时按上文 PATH 覆盖 |
| `Daemon process exited during startup with no error output` | 通常是前置条件（daemon 用的子进程 Node 崩了），即使 `--version` 正常 | 跑 Node 检查。`--debug` 往往也看不到东西，因为子 Node 在产出输出前就崩了 |
| `browserType.launch: Executable doesn't exist` / Chromium 版本错配 | 执行原则（渠道错了） | 重跑 `agent-browser install`。仍错配则用**自带的** CLI：<br>`node "$(npm root -g)/agent-browser/node_modules/playwright-core/cli.js" install chromium`（Windows 用 `$(npm root -g)\agent-browser\node_modules\playwright-core\cli.js`） |
| `npx playwright install` 被 SIGTERM / 超时 | 执行原则（渠道错了） | 停用 `npx playwright install`，回到上面的自带渠道 |
| 装完仍 `command not found` | 都不是，是 shell / PATH 问题 | 重开 shell；`npm config get prefix` 确认全局 bin 在 PATH |
| Linux 启动缺系统库 | 都不是，是 OS 依赖 | `agent-browser install --with-deps` |
| `scripts/setup.sh` 跑完仍 `command not found` | shell PATH 没刷新 | 重开终端，先确认 `agent-browser --version` 能跑再继续 |

**通用铁律**：任务成功或失败，**结尾都必须 `agent-browser close`**，否则留下僵尸 daemon 和游离 Chromium 进程。

**假性挂起（本机实测坑）**：daemon 会继承父进程 stdout，冷启动时若接了管道（如 `| head`），`head` 永远等不到 EOF：

```bash
# ❌ 看起来像 daemon 起不来
timeout 90 agent-browser open https://example.com | head -20
# ✅ 重定向到文件
agent-browser open https://example.com > /tmp/ab.log 2>&1
```

更多 agent-browser 用法与登录态复用见 [浏览器自动化](浏览器自动化.md)。

## 2. CDP Proxy（L1）

| 症状 | 原因 | 解决 |
|---|---|---|
| `Chrome 未开启远程调试端口` | 浏览器没开调试开关 | 地址栏打开 `edge://inspect/#remote-debugging`（Chrome 用 `chrome://...`），勾选 **Allow remote debugging for this browser instance**。一次性操作，长期有效 |
| `attach 失败` | `targetId` 失效或 tab 已关 | `curl -s http://localhost:3456/targets` 取最新列表 |
| `CDP 命令超时` | 页面长时间无响应 | 重试；或 `/info` 看 tab 状态，必要时 `/close` 后重建 |
| `端口已被占用` | 已有 proxy 在跑 | **直接复用**，不要再起一个 |
| 调用返回 400 且含 `migration` | 用了 v2.5.2 的 `GET ?url=` 旧写法 | 改成 POST body，见 [CDP-API参考](CDP-API参考.md) |
| 切浏览器后行为异常 | proxy 是长驻进程，仍连着旧浏览器 | `pkill -f cdp-proxy.mjs` 再重跑 `check-deps.mjs` |
| `/new` 返回了但内容空 | 就绪判断问题，不是 CDP 问题 | 导航后用 `/eval` 检查目标内容，15 秒窗口内持续观察 |
| `/eval` 报序列化错误 | 直接返回了 DOM 节点 | 改为返回属性：`el.innerText`、`el.getAttribute('href')`；批量数据用 `JSON.stringify()` 包裹 |

## 3. pw.mjs / Playwright

| 症状 | 原因 | 解决 |
|---|---|---|
| `[pw] 未找到本地 playwright` | `node_modules` 没装 | `cd 联网工具箱 && npm install` |
| 快照看不到内容 | 快照默认**写文件**，不打印 stdout | `cat .playwright-cli/page-*.yml`；或建 `playwright-cli.json`：`{"outputMode":"stdout"}` |
| `Unknown option: --browser` | 只有 `open` 接受 `--browser` | 确认 `pw.mjs` 是最新版（已修）；或把 `--browser=msedge` 只加在 `open` 上 |
| 截图失败 | 浏览器还没 open | 先 `open` |
| 看不到登录态 | 默认隔离上下文（等同无痕） | 用 `--persistent` / `--profile`，或直接回 CDP 直连 |
| 僵尸进程残留 | — | `node scripts/pw.mjs kill-all` |
| 页面永不 idle，`wait` 挂住 | SPA 常见 | 别死等 `networkidle`，改用元素/函数等待，见 [playwright高级用法](playwright高级用法.md) |

Playwright 的高级命令见 [playwright高级用法](playwright高级用法.md)。

## 4. Python 抓取栈（venv）

### 症状：`pip` 自己坏了

```
No module named pip.__main__; 'pip' is a package and cannot be directly executed
```

此时**所有 pip 安装都会失败，但报错看起来像网络超时**——极易误判为网络问题。

```bash
SP="C:/Users/Matebook/.workbuddy/binaries/python/envs/default/Lib/site-packages"
PY="C:/Users/Matebook/.workbuddy/binaries/python/envs/default/Scripts/python.exe"
mv "$SP/pip" "$SP/pip.broken.bak"
mv "$SP/pip-26.1.2.dist-info" "$SP/pip-26.1.2.dist-info.bak"   # 残留 dist-info 会让 ensurepip 跳过
"$PY" -m ensurepip --upgrade --default-pip
"$PY" -m pip -V
rm -rf "$SP/pip.broken.bak" "$SP/pip-26.1.2.dist-info.bak"
```

### 症状：某个包被「剥离」

目录还在，`.py` / `.pyd` 不见了，只剩 `__pycache__`。`import` 报 `ModuleNotFoundError` 但 `pip list` 显示已安装。
`pip` **卸不掉它**（`The package's contents are unknown: no RECORD file was found`），必须手工删目录再装：

```bash
rm -rf "$SP/lxml" "$SP/lxml-6.1.1.dist-info"
"$PY" -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple lxml lxml_html_clean
```

### 两个使用要点

- **pip 是整体回滚**：一批里有一个包失败，整批都不装 → 分批装，或一次只装一个
- **加 `--timeout 120 --prefer-binary`**：本机默认 15s 超时太短
- **必须用清华源** `-i https://pypi.tuna.tsinghua.edu.cn/simple`（默认源在本机频繁超时）

## 5. 本机网络环境的固有坑

| 现象 | 真相 |
|---|---|
| `curl` 报 `schannel: CRYPT_E_NO_REVOCATION_CHECK (0x80092012)`，HTTP 000 | 校园网卡证书吊销检查。**加 `--ssl-no-revoke` 即可通** |
| hfut 域名走代理 502，直连 0.1 秒 | 本机代理对 hfut 域返回 502。抓 hfut 必须绕过代理：`requests.Session().trust_env=False`，或 urllib 用 `build_opener(ProxyHandler({}))` |
| 某个 RSS 源返回 200 但 body 为 0 字节 | HTTP 200 **不代表有内容**（本工具箱实测到的「假活」源） |
| Jina（`r.jina.ai`）不可达 | 本机实测不可达，**不要作为默认路径** |
| Bash 沙箱内连不上 `127.0.0.1:xxxx` | 沙箱阻断 loopback。需要访问本地服务时加 `dangerouslyDisableSandbox: true` |

## 6. 排障心法

1. **先跑 `doctor.mjs`**，让环境自己说话，别照文档猜
2. **拿到真实报错再对症**——本页按症状索引就是为了这个
3. **同一方式不重复重试两次以上**：报错无改善就是在提示方向错了，换层或换路径
4. **区分「没找到」和「不存在」**：搜索无结果 ≠ 方法不对，也可能是目标确实不存在
5. **本工具箱历史上三处文档错误**（`@playwright/mcp` 误当 `playwright-cli`、`human-browser-cli`（npm 404）、`agent-browser act`（不存在））都源于「照抄文档不验证」。**装包前先核实包存在**：
   ```bash
   curl -o /dev/null -w '%{http_code}' https://registry.npmjs.org/<包名>
   curl -o /dev/null -w '%{http_code}' https://pypi.org/pypi/<包名>/json
   ```
   404 = 不存在。
