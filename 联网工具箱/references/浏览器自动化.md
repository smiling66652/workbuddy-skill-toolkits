|------|------|------|------|------|------|
| **CDP 直连**（见 CDP浏览器直连.md） | 8ms | 中高² | ✅ 天然继承 | ✅ 可用 | **P0 首选** |

| **Agent Browser** | 45ms 起 | 中高 | ✅ `--cdp` / `--profile` | ❌ **未安装**（仅剩缓存） | AI 友好快照 + 视觉标注 |

## 三级：Playwright（功能最全）—— 本机走 `scripts/pw.mjs`，无需全局安装

**先问一句**：目标站点你已在本机浏览器登录过吗？是 → 回 [CDP浏览器直连](CDP浏览器直连.md)，别在这重建登录态。

### 本机现状（2026-09-12 实测）

| 项 | 结论 |
|---|---|
| 工具箱自带 `node_modules/playwright` | ✅ **1.63.0**，其内置 `cli` 子命令 ≈ 全局 `playwright-cli` |
| 调用方式 | ✅ `node scripts/pw.mjs <命令>`（零安装，默认走系统 Edge） |
| npm 全局 `playwright-cli` | ⚠️ 存在但**是废弃占位包**（`package.json` 写着 "Deprecated package, use @playwright/cli instead."），无实际功能 |
| 正确包名（真要全局装） | `npm install -g @playwright/cli` |

```bash
node scripts/pw.mjs --self-check          # 确认本地 playwright 可用
# 真要全局装：
npm install -g @playwright/cli            # ✅ 正确包名
# playwright-cli install-browser          # 需要自带浏览器时才跑；用系统 Edge 可不跑
```

> ❌ **不要再写 `npm install -g @playwright/mcp@latest`**。`@playwright/mcp` 是另一个真实存在但用途不同的包（MCP 服务端），装它得不到 `playwright-cli` 命令。
>
> ❌ 也不要装 npm 上的裸名 `playwright-cli` —— 已被官方废弃为占位包。
>
> 请求 mock / 状态存取 / trace / 录屏 / 生成测试代码等高级用法见 [playwright高级用法](playwright高级用法.md)。

### 常用操作

```bash
playwright-cli open                       # 打开浏览器
playwright-cli open https://example.com/  # 打开并导航
playwright-cli open --browser=msedge      # 用系统 Edge（无需下载浏览器）
playwright-cli snapshot                   # 取元素引用 → 写入 .playwright-cli/*.yml
cat .playwright-cli/page-*.yml            # ⚠️ 快照默认写文件，不打印到 stdout
playwright-cli click e3                   # 用快照里的 ref 点击
playwright-cli fill e5 "user@example.com"
playwright-cli screenshot
playwright-cli close
```

**快照输出到文件是本层最大的坑**。想让它走 stdout，可建 `playwright-cli.json`：`{ "outputMode": "stdout" }`

### 独有能力（CDP / eval 做起来费劲的）

这些是本层真正的价值，不要只把它当"点击器"：

```bash
playwright-cli pdf --filename=page.pdf           # 页面转 PDF
playwright-cli route "**/*.jpg" --status=404     # 请求拦截 / mock
playwright-cli cookie-list --domain=example.com  # Cookie 细粒度读写
playwright-cli localstorage-get theme            # localStorage / sessionStorage
playwright-cli state-save auth.json              # 存取整套登录态，跨会话复用
playwright-cli network                           # 网络日志
playwright-cli console                           # 控制台日志
playwright-cli tracing-start / tracing-stop      # trace 录制回放
playwright-cli video-start / video-stop x.webm   # 录屏
playwright-cli upload ./document.pdf             # 文件上传
playwright-cli run-code "async page => await page.context().grantPermissions(['geolocation'])"
```

### 持久化会话（保持登录态）

```bash
playwright-cli -s=wenku open https://wenku.baidu.com/ --persistent
playwright-cli -s=wenku click e6
playwright-cli -s=wenku close        # 下次 -s=wenku 仍在
playwright-cli list / close-all / kill-all
```

**反检测基础配置**（默认配置会被 Cloudflare 秒拦）：

```bash
playwright-cli open --browser=msedge
# 若必须独立实例：加 --disable-blink-features=AutomationControlled
# 并注入 addInitScript 覆盖 navigator.webdriver
```

其余手段见 [反爬对抗](反爬对抗.md)——**不要在 Playwright 上死磕 Cloudflare，先上 CDP 直连**。

## 三级：Agent Browser（AI 友好，⚠️ 本机未安装）

### 与 Playwright CLI 的分工

| | Agent Browser | Playwright CLI |
|---|---|---|
| 页面表示 | accessibility tree + `@ref`（省 token） | snapshot yml |
| 视觉理解 | ✅ `screenshot --annotate` 给元素打编号标签 | 普通截图 |
| 复用登录态 | ✅ `--cdp 9222` / `--profile Default` | ⚠ 需 `--persistent` |
| 网络 mock / trace / 录屏 | ❌ | ✅ |
| 会话模型 | 常驻 daemon | 每命令一个会话 |

**结论**：要"看懂页面 + 复用登录态"用 Agent Browser；要做网络 / 调试 / 录制用 Playwright CLI。

### 安装（⚠️ CLI 已不在本机，需重装）

2026-09-12 实测：`agent-browser` 不在 PATH，npm 全局（`AppData/Roaming/npm/node_modules`）
与托管 node 全局（`binaries/node/versions/22.22.2-3/node_modules`）都没有它。
残留物只有 `~/.agent-browser/`：`browsers/chrome-152.0.7977.82` + 陈旧状态文件。

```bash
npm install -g agent-browser
agent-browser install        # 可复用已缓存的 ~/.agent-browser/browsers/chrome-152.x
```

> ❌ **不存在 `npx @agent-browser/cli install`，也不存在 `agent-browser act "..."` 子命令**。
> 本机实测 `agent-browser --help` 无 `act`。用自然语言操作浏览器是别家产品的宣传语，不是这个 CLI 的能力。
>
> 装好后务必先跑 `node -e "console.log('ok')"` —— 见 [故障诊断](故障诊断.md) 的 Node 前置检查。

### 核心工作流：先取 ref，再操作

```bash
agent-browser open https://example.com
agent-browser snapshot -i            # -i = 只要可交互元素，带 @e1/@e2 引用
agent-browser click @e2              # 用 ref 点击（不要盲猜 CSS 选择器）
agent-browser fill @e3 "test@x.com"
agent-browser get text @e1           # 定向取值
agent-browser close
```

### 会话模型（决定成败）

- 首次 `open` 启动**常驻 daemon**；后续命令自动连同一个 daemon
- **同一 session 内 Cookie / localStorage / 登录态跨命令保留**
- 同一 session 内多次 `open` 是**导航**，不要中途 `close`
- `close` 只在**整个任务结束时**调用一次；任务中途 close 会丢登录态

```bash
# ✅ 一次 open 走完 N 个页面，最后 close
agent-browser open a.com && agent-browser snapshot -i
agent-browser open b.com && agent-browser snapshot -i
agent-browser close
```

### 复用登录态（本机最实用的一条）

```bash
agent-browser --cdp 9222 snapshot        # 连已开远程调试端口的浏览器 → 默认上下文 → 看到你的登录态
agent-browser --auto-connect snapshot    # 自动发现正在运行的 Chrome / Edge
agent-browser --profile Default open gmail.com   # 用 Chrome 的 Default 档案（需先关掉其他浏览器窗口）
agent-browser profiles                   # 列出可用档案
agent-browser --session-name myapp open x.com    # 自动保存 / 恢复状态
```

> `--cdp` 走的是 Chrome 的**默认上下文**（真实 cookie jar），这是它和 standalone 模式的本质差别。
> 有了它，本技能的 CDP Proxy 挂掉时本层能顶上，**不必重建登录态**。

### ⚠️ 冷启动 + 管道 = 假性挂起（本机实测坑）

`agent-browser` 的 daemon 会**继承父进程 stdout**。冷启动时如果输出接了管道，`head` 会一直等不到 EOF：

```bash
# ❌ 冷启动时这样写会假性挂起（看起来像 daemon 起不来）
timeout 90 agent-browser open https://example.com | head -20

# ✅ 重定向到文件，或先预热 daemon 再随便接管道
agent-browser open https://example.com > /tmp/ab.log 2>&1
```

这个坑会伪装成"环境坏了"，排查半天其实只是管道。doctor.mjs 已内置该提示。

### 其他有用命令

```bash
agent-browser wait 2000                  # 等页面稳定（比 wait --load networkidle 更稳，SPA 常不 idle）
agent-browser screenshot --full           # 整页截图
agent-browser screenshot --annotate       # 元素打编号标签，给视觉模型看
agent-browser find role button click --name Submit   # 语义定位
agent-browser is visible @e2 / get url / get count "li"
agent-browser download @e5 ./out.pdf      # 点击元素触发下载
agent-browser pdf ./page.pdf
agent-browser --color-scheme dark open x.com
agent-browser skills get core --full      # 版本匹配的官方命令手册（比查网页准）
```

**执行铁律**：`close` 必须放在 finally —— 任务成功或失败都要调，否则留僵尸 daemon 和游离 Chromium 进程。

## 手动登录中断-恢复机制

自动登录不可行、且用户本机未登录时（P2 兜底）：

1. **检测登录需求** — URL 跳登录页 / 出现登录弹窗 / 内容被遮罩提示"请登录"
2. **切换有头浏览器** — 启动 headed 实例（不要 headless，headless 指纹更易被拦）
3. **通知用户** — 说清是哪个网站、当前页面什么状态
4. **轮询登录完成** — 每 3 秒检查 URL 恢复 / DOM 出现正文 / 弹窗消失；默认超时 120 秒后询问用户
5. **恢复自动化** — 用户确认后继续，不要重启浏览器（会丢会话）

> **更省事的做法**：若该站你本机浏览器已登录，直接用 CDP 直连（L1），根本不需要中断流程。

## 故障排查

| 现象 | 真实原因 / 解决 |
|------|-----------|
| `playwright-cli` 未找到 | `npm install -g @playwright/cli`（**不是** `@playwright/mcp`） |
| `agent-browser` 未找到 | `npm install -g agent-browser && agent-browser install`；装完重启 shell 或确认 npm 全局 bin 在 PATH |
| agent-browser 像卡死不动 | **冷启动接了管道**。重定向到文件（见上文"假性挂起"） |
| agent-browser 看不到我的登录态 | standalone 模式是隔离上下文；加 `--cdp 9222` 或 `--profile Default` |
| playwright-cli snapshot 没输出 | 快照默认写 `.playwright-cli/*.yml`，去 cat 文件或设 `outputMode: stdout` |
| 截图失败 | 先确认浏览器已 open |
| 遇到 Cloudflare / Turnstile | **不要**在这层硬试；转 [反爬对抗](反爬对抗.md) |
| 装完 CLI 仍报缺 Chromium 依赖（Linux） | `agent-browser install --with-deps` |
| Node 报 SIGILL / exit 133 | PATH 上的 node 能打印版本但不能执行代码，换托管 Node 22.22.2-2 |
