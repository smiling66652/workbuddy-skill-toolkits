# 二级：代码审查

**适用场景**：用户需要对代码进行安全审查、性能分析、可维护性评估。

---

## 三级执行：代码审查流程

### 审查维度

| 维度 | 检查项 | 工具 |
|------|--------|------|
| **安全** | SQL注入、XSS、CSRF、敏感信息泄露 | Bandit, Semgrep, CodeQL |
| **性能** | 时间复杂度、内存泄漏、数据库N+1 | pylint, perflint, memory_profiler |
| **可维护性** | 代码复杂度、重复代码、命名规范 | radon, flake8, pylint |
| **测试覆盖** | 单元测试、集成测试、E2E测试 | pytest-cov, coverage.py |

## 安全审查

### Python 安全审查（Bandit）

```bash
# 安装
pip install bandit

# 扫描整个项目
bandit -r ./my_project -f json -o security_report.json

# 只扫描高危问题
bandit -r ./my_project --severity-level high

# 生成HTML报告
bandit -r ./my_project -f html -o security_report.html
```

**常见安全问题**：

| 问题 | 危险等级 | 修复建议 |
|------|---------|---------|
| 硬编码密码 | 高 | 使用环境变量或配置文件 |
| `eval()` / `exec()` | 高 | 避免使用，或严格限制输入 |
| SQL拼接 | 高 | 使用参数化查询 |
| 不验证输入 | 中 | 添加输入验证和转义 |
| 敏感信息日志 | 中 | 避免记录密码、Token等 |

### 多语言安全审查（Semgrep）

```bash
# 安装
pip install semgrep

# 扫描项目（使用内置规则）
semgrep --config=auto ./my_project

# 扫描特定语言
semgrep --lang=python --config=security ./my_project

# 输出JSON报告
semgrep --config=auto ./my_project --json -o security_report.json
```

### 深度安全分析（CodeQL）

```bash
# 安装 CodeQL CLI
# 从 https://github.com/github/codeql-cli-binaries/releases 下载

# 创建数据库
codeql database create py-database --language=python --source-root=./my_project

# 运行查询
codeql database analyze py-database security-and-quality.qls --format=csv --output=results.csv
```

## 性能审查

### Python 性能分析

```bash
# 安装性能分析工具
pip install py-spy memory_profiler line_profiler

# CPU性能分析（py-spy）
py-spy record -o profile.svg --duration 60 -- python app.py

# 内存分析（memory_profiler）
python -m memory_profiler my_script.py

# 逐行分析（line_profiler）
kernprof -l -v my_script.py
```

### 常见性能问题

| 问题 | 检测工具 | 修复建议 |
|------|---------|---------|
| 循环内重复查询数据库 | django-debug-toolbar | 使用 `select_related` / `prefetch_related` |
| 大文件一次性读取 | memory_profiler | 使用生成器或分块读取 |
| 全局解释器锁(GIL) | py-spy | 使用多进程替代多线程 |
| 不必要的内存拷贝 | tracemalloc | 使用视图或原地操作 |
| 算法复杂度高 | radon | 优化算法，使用合适的数据结构 |

### JavaScript/TypeScript 性能分析

```bash
# 使用 Chrome DevTools Profiler
# 1. 打开 Chrome DevTools → Performance
# 2. 开始录制 → 执行操作 → 停止录制
# 3. 分析火焰图

# 使用 Node.js Profiler
node --prof app.js
node --prof-process isolate-*.log > processed.txt
```

## 可维护性审查

### 代码复杂度分析（radon）

```bash
# 安装
pip install radon

# 计算圈复杂度
radon cc ./my_project -a -nc

# 计算可维护性指数
radon mi ./my_project -nc

# 输出JSON格式
radon raw ./my_project -j
```

**复杂度等级**：

| 等级 | 复杂度 | 说明 |
|------|--------|------|
| **A** | 1-5 | 简单，容易维护 |
| **B** | 6-10 | 稍微复杂，可接受 |
| **C** | 11-20 | 复杂，建议重构 |
| **D** | 21-30 | 很复杂，必须重构 |
| **E/F** | 31+ | 极其复杂，不可维护 |

### 代码风格检查（flake8/pylint）

```bash
# flake8（轻量）
pip install flake8
flake8 ./my_project --max-line-length=120 --output-file=style_report.txt

# pylint（全面）
pip install pylint
pylint ./my_project --output-format=json > pylint_report.json
```

### 重复代码检测（jscpd）

```bash
# 安装
npm install -g jscpd

# 检测重复代码
jscpd ./my_project --languages python,javascript --reporters json --output jscpd_report/
```

## 自动化代码审查

### Git pre-commit hook

创建 `.git/hooks/pre-commit`：

```bash
#!/bin/bash
echo "运行代码审查..."

# 安全审查
bandit -r ./my_project -ll ERROR
if [ $? -ne 0 ]; then
  echo "安全审查失败，禁止提交"
  exit 1
fi

# 代码风格检查
flake8 ./my_project --max-line-length=120
if [ $? -ne 0 ]; then
  echo "代码风格检查失败，请修复后重新提交"
  exit 1
fi

echo "代码审查通过"
```

### CI/CD集成

`.github/workflows/code-review.yml`：

```yaml
name: Code Review

on: [push, pull_request]

jobs:
  security:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Set up Python
        uses: actions/setup-python@v4
        with:
          python-version: '3.11'
      - name: Install dependencies
        run: pip install bandit semgrep
      - name: Run security check
        run: |
          bandit -r ./my_project -f json -o bandit-report.json
          semgrep --config=auto ./my_project --json -o semgrep-report.json
      - name: Upload reports
        uses: actions/upload-artifact@v3
        with:
          name: security-reports
          path: "*-report.json"
```

## 代码审查清单

### 提交前自查清单

```
安全措施
  ├── [ ] 没有硬编码密码/API Key
  ├── [ ] 所有用户输入都经过验证和转义
  ├── [ ] 数据库查询使用参数化查询
  ├── [ ] 敏感操作需要权限验证
  └── [ ] 错误信息不暴露敏感数据

性能优化
  ├── [ ] 没有N+1查询问题
  ├── [ ] 大文件使用流式处理
  ├── [ ] 热点代码添加了缓存
  └── [ ] 算法复杂度合理（O(n²)警告）

可维护性
  ├── [ ] 函数长度 < 50行
  ├── [ ] 圈复杂度 < 10
  ├── [ ] 变量/函数命名清晰
  ├── [ ] 添加了必要的注释
  └── [ ] 没有重复代码

测试覆盖
  ├── [ ] 新增功能有单元测试
  ├── [ ] 测试覆盖率 > 80%
  └── [ ] 边界条件有测试
```

## 与 WorkBuddy 集成

### 自动代码审查

在提交代码前，让 WorkBuddy 自动运行：

```bash
# 安全审查
bandit -r . -f json -o security.json
if [ $(jq '.results | length' security.json) -gt 0 ]; then
  echo "发现安全问题，禁止提交"
  exit 1
fi

# 性能分析
pylint . --output-format=json > pylint.json
if [ $(jq '[.[] | select(.type=="error")] | length' pylint.json) -gt 0 ]; then
  echo "发现性能问题，请修复后重新提交"
  exit 1
fi
```

## 故障排查

| 问题 | 解决方案 |
|------|-----------|
| Bandit扫描太慢 | 排除测试目录 `bandit -r . -x ./tests` |
| Semgrep规则太多误报 | 自定义规则文件，只启用需要的规则 |
| pylint太严格 | 创建 `.pylintrc` 配置文件，禁用不需要的检查 |
| 性能分析影响生产环境 | 只在开发/测试环境启用性能分析 |

---

## 注意事项

1. **自动化工具不能完全替代人工审查** — 工具只能发现常见问题，业务逻辑漏洞需要人工审查
2. **平衡严格度和开发效率** — 过于严格的规则会降低开发效率
3. **定期更新工具和规范** — 安全威胁和最佳实践在不断演进
4. **团队统一标准** — 确保团队成员使用相同的工具和配置
