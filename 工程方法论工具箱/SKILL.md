# 工程方法论工具箱

> 解决的是「会做，但做得不稳」的问题。领域技能决定你能不能做出来，方法论决定你做出来可不可靠。
>
> **本工具箱的方法论融合自 GitHub 项目 `obra/superpowers`（283,591 stars，2026-09 核实），
> 并针对中文语境与本地 Windows 环境做了改写。**

---

## 一级：判断当前处境

先问自己：**我现在处在哪个环节？** 不要跳步。

| 处境 | 典型信号 | 跳到二级 |
|---|---|---|
| **出了 bug / 报错 / 行为不符预期** | 测试挂了、构建失败、程序崩溃、结果不对 | 系统化调试 |
| **要写新功能 / 修 bug / 重构** | 准备动手写产品代码 | 测试驱动开发 |
| **准备说「做完了」「修好了」「通过了」** | 要提交、要交付、要汇报 | 完成前验证 |
| **要评审别人的代码 / 自己复查** | 收到 PR、写完一大段代码 | 代码审查 |
| **需求含糊、不确定要做什么** | 用户说得很笼统、有多种解法 | 需求澄清 |

**多个处境同时命中时**，按 **需求澄清 → 系统化调试 / TDD → 完成前验证** 的顺序走。

---

## 二级：三条铁律（先看这个）

这三条是整个工具箱的底线，违反字面规定就是违反精神。

### 铁律一：没找到根因，不许动手修

```
NO FIXES WITHOUT ROOT CAUSE INVESTIGATION FIRST
```

**典型违规**：报错了先改一行试试，改完不报错就当修好了。
**危害**：症状消失 ≠ 问题消失，同样的 bug 下周换个形式再来一次。
**尤其危险的场景**：时间紧、觉得"就是个小问题"、已经试了好几种改法、前一次修复没生效。

> 详见 `references/系统化调试.md`

### 铁律二：没有失败的测试，不许写产品代码

```
NO PRODUCTION CODE WITHOUT A FAILING TEST FIRST
```

**核心逻辑**：如果你没亲眼看见测试失败，你就不知道这个测试到底在测什么。
先写代码再补测试 = 测试只是在描述已有行为，不是在约束期望行为。

> 详见 `references/测试驱动开发.md`

### 铁律三：没有新鲜的验证证据，不许宣称完成

```
NO COMPLETION CLAIMS WITHOUT FRESH VERIFICATION EVIDENCE
```

**注意「新鲜」二字**：上一次跑过不算，别人说通过了不算，agent 报告 success 不算。

| 你要宣称 | 必须有的证据 | 不算数的 |
|---|---|---|
| 测试通过 | 本次运行的测试输出，0 failures | 上次跑过 / "应该能过" |
| 构建成功 | 构建命令 exit 0 | 日志看着没问题 |
| bug 修好了 | 用原始症状复测，通过 | 代码改了，假定修好了 |
| 需求满足了 | 逐条对照清单 | 测试通过（测试可能测错了） |
| **子 agent 完成了** | **VCS diff 显示真实改动** | **agent 自己汇报 success** |

> 详见 `references/完成前验证.md`

## 三级：读取对应方法论

根据一级判断，读取 `references/` 下的文件，严格按步骤执行：

| 方法论 | 文件 | 核心动作 |
|---|---|---|
| 系统化调试 | `references/系统化调试.md` | 四阶段：读错误 → 稳定复现 → 查变更 → 定位根因，然后才能修 |
| 测试驱动开发 | `references/测试驱动开发.md` | 红 → 绿 → 重构，循环 |
| 完成前验证 | `references/完成前验证.md` | 识别验证命令 → 跑 → 读输出 → 确认 → 才开口 |

| 需求澄清 | `references/需求澄清.md` | 先问清再动手，一次问到位 |

## 本地化补充（Windows / 中文环境）

1. **验证命令要能在 Git Bash 里跑通**：优先用绝对路径调用受管 Python / Node，避免版本不一致导致的假失败。
   - Python：`C:\Users\Matebook\.workbuddy\binaries\python\versions\3.13.12\python.exe`
   - Node：`C:\Users\Matebook\.workbuddy\binaries\node\versions\22.22.2-3\node.exe`（2026-09-15 实测；`versions\` 下只有 22.22.2-3，`current` 是标记文件不是目录）
2. **中文路径**：Windows 下路径含中文时，脚本里用宽字符 API 或显式 UTF-8 声明；`\\?\` 前缀可绕过路径规范化但对保留名文件无效。
3. **验证输出要看退出码**：Git Bash 里用 `echo "exit=$?"`，不要只看 stdout 有没有内容。

- 具体领域能力走对应的技能包：文档处理 → `文档工具箱`，联网 → `联网工具箱`，代码提交 → `git-ship`。
