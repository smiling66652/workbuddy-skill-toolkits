# 完成前验证

> 融合自 `obra/superpowers/skills/verification-before-completion`。

## 铁律

```
NO COMPLETION CLAIMS WITHOUT FRESH VERIFICATION EVIDENCE
```

**没在本轮对话里跑过验证命令，就不能说它通过了。**

关键词是「**新鲜**」：上次跑过不算、别人说通过不算、agent 汇报成功不算。

## 门禁五步

在说出任何「做完了 / 修好了 / 通过了」之前：

```
1. 识别：什么命令能证明这个结论？
2. 运行：完整执行该命令（本轮、完整、不加过滤）
3. 读取：看完整输出，检查退出码，数失败数量
4. 确认：输出真的支持这个结论吗？
   - 不支持 → 如实说明实际状态，附证据
   - 支持   → 说出结论，同时附上证据
5. 只有到这一步，才开口说完成
```

跳过任何一步 = 在撒谎，不是在验证。

## 证据对照表

| 你要宣称 | 必须有的证据 | 不算数的 |
|---|---|---|
| 测试通过 | 本次测试输出：0 failures | 上一次跑过 / "应该能过" |
| lint 干净 | lint 输出：0 errors | 只查了一部分 / 推断 |
| 构建成功 | 构建命令 exit 0 | lint 过了 / 日志看着正常 |
| bug 修好了 | 用原始症状复测且通过 | 代码改了，假定好了 |
| 回归测试有效 | 验证过红→绿循环 | 测试通过一次 |
| **子 agent 完成了** | **VCS diff 显示真实改动** | **agent 自己汇报 success** |
| 需求都满足了 | 逐条对照的检查清单 | 测试通过（测试本身可能测错） |

## 红旗 —— 出现这些词立刻停下

- 用了「应该」「大概」「似乎是」
- 验证之前就表达满意（"太好了！""完美！""搞定了！"）
- 只跑了一部分就外推到整体
- 拿「之前跑过」当证据
- 用别人的汇报代替自己的验证

## 子 agent 场景（重点）

派出去的 agent 汇报成功时，**必须自己验证**：

```bash
git status --short          # 真的有改动吗？
git log --oneline -3        # 真的提交了吗？
git diff --stat             # 改动范围对吗？
grep -rIn "<关键值>" .      # 声称清理干净的东西真的清了吗？
```

**不要因为 agent 说"已完成"就 mark completed。** 这是本条方法论最容易被违反的地方。

## 本地化提示

- Git Bash 里验证退出码：`命令; echo "exit=$?"`
- 验证输出可能被截断，长输出加 `| tail -30` 或 `| head -40`，但**别用 `grep` 过滤掉失败信息**
- Windows 下路径含空格/中文要加引号
