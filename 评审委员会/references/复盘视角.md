# 复盘视角（retro）

> 融合自 `garrytan/gstack` 的 `retro`，**只保留单人可用部分**。
> 把关：过程度量——是否碎片化、是否总在修 bug。**不管单次改动对错。**
>
> 用户环境：Windows + Git Bash。下面所有命令直接在 Git Bash 里跑（项目根目录）。

---

## 本地化裁剪声明（重要）

> gstack 原版 retro 包含大量**团队/多人**度量：per-author leaderboard（谁提交最多）、
> 多贡献者协作分析、跨团队成员负载等。**个人项目里这些全是废的**——只有一个贡献者，
> 没有「谁拖了后腿」「谁该多担待」的问题。因此本文件**明砍**：
> - ❌ per-author leaderboard（单人无意义）
> - ❌ 多贡献者协作/负载分析（没有第二个人）
> - ❌ 跨团队节奏统计（无团队）
>
> 只保留**从你自己的 git history 算出来的、能帮你改进下次开发的指标**。

---

## 五个可量化指标

| 指标 | 含义 | 预警线 |
|---|---|---|
| 逻辑 SLOC | 实际代码量（去空行/注释） | 配合测试比看健康度 |
| 测试比 | 测试文件 / 代码文件 | 越低越脆 |
| **fix ratio** | 修复类提交占比 | **> 50% = 警示**（总在救火） |
| hotspot churn | 反复改动的文件 | 高 = 设计不稳定/需求飘 |
| Focus Score | 提交是否碎片化 | 见下方判据 |

---

## Git Bash 实测命令（项目根目录运行）

### 1. 逻辑 SLOC（去掉空行与注释的近似）
```bash
# 总量（按语言示例，可自行增删扩展名）
git ls-files | grep -E '\.(py|js|ts|vue|java|cpp)$' \
  | xargs grep -vcE '^\s*(#|//|/\*|\*|$)' \
  | awk -F: '{s+=$2} END{print "逻辑SLOC:", s}'
```
> 说明：用 `grep -v` 排除空行与常见注释开头，是近似而非严格 SLOC（无 cloc 时够用）。
> 若装了 `cloc` 则 `cloc $(git ls-files)` 更准。

### 2. 测试比
```bash
echo -n "测试文件数: "; git ls-files | grep -iE 'test|spec|__tests__' | wc -l
echo -n "代码文件数: "; git ls-files | grep -E '\.(py|js|ts|vue|java|cpp)$' | wc -l
```

### 3. fix ratio（修复类提交占比）
```bash
total=$(git rev-list --count HEAD 2>/dev/null)
fixes=$(git log --oneline | grep -ciE 'fix|修复|bug|修正|hotfix')
if [ "$total" -gt 0 ] 2>/dev/null; then
  echo "总提交: $total  修复类提交: $fixes  修复比: $((fixes*100/total))%"
else
  echo "无提交记录或无法统计"
fi
```
> **> 50% = 警示**：说明你大部分时间在修 bug 而非做新东西，可能需求不清 / 测试不足 / 架构不稳。

### 4. hotspot churn（反复改动的文件 Top 20）
```bash
git log --pretty=format: --name-only | grep -v '^$' \
  | sort | uniq -c | sort -rn | head -20
```
> 排在前面的文件 = 反复被改。若同一个文件月月改，要么它职责太重，要么需求一直变。

### 5. Focus Score（提交碎片化度量）
```bash
git log --no-merges --name-only --pretty=format: | awk '
  NF { cnt++ }
  /^$/ { if (cnt>0) { n++; sum+=cnt; cnt=0 } }
  END { if (cnt>0) { n++; sum+=cnt }
        if (n>0) printf "有效提交次数: %d  平均每次改动文件数: %.2f\n", n, sum/n }'
```
判据（单人项目经验值）：
- **平均每次改动文件数 > 8**：提交粒度偏大，一次动太多不相关文件，回滚困难 → 建议拆小。
- **同时** fix ratio 高 + hotspot 集中：典型「架构没定型就猛写」，下次先花时间定结构。
- **碎片化反面**（大量 1 行提交）：也非好事，说明没想清楚就提交。理想是「一次一个完整小功能」。

> Focus Score 这里用「平均每次改动文件数」作为代理指标。gstack 原版的 Focus 是团队节奏，
> 单人项目没有节奏可言，用「提交粒度」替代最有用。

## 复盘输出模板

```
## 项目复盘（<项目名>）
- 逻辑SLOC: ___   测试比: ___/___
- 修复比: ___%   （>50% 警示）
- 反复改动文件: ___ (Top3)
- 提交粒度: 平均每次 ___ 个文件
- 主要问题: ___
- 下次改进: ___
```

> 融合说明：指标定义参考 gstack retro，但**命令与判据是按 Windows+Git Bash+单人项目重写**的，
> 砍掉了所有多贡献者分析，保证用户在自己电脑上能直接跑出数字。
