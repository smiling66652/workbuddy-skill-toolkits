# QA 视角（qa）

> 融合自 `garrytan/gstack` 的 `qa`。把关：真实行为验证、回归、边界、证据。**不管设计意图。**
>
> QA 视角的灵魂一句话：**没有前后对比证据的修复，不算验收通过。**

---

## 验证手段：真实优先，headless 回退

1. **真实浏览器验证优先**：能真开浏览器（含小程序真机/模拟器、网页真打开）就别用无头模式。无头会漏掉视觉、交互、布局问题。
2. **headless 作为回退**：CI 环境、无显示界面时才用无头浏览器（Playwright headless、puppeteer）。
3. **命令行程序**：直接在 Git Bash 跑真实命令，看真实 stdout/stderr 与 exit code——不要「看代码推断应该没问题」。

---

## 验收分级（按任务选档，不要每档都做满）

| 档位 | 适用 | 做什么 |
|---|---|---|
| **Quick** | 小改动、单点修复 | 跑通主路径 1 次 + 看关键输出，确认无回归 |
| **Standard** | 常规功能 / PR | Quick + 边界条件（空/大/异常）+ 关键回归测试 |
| **Exhaustive** | 核心模块 / 上线前 / 竞赛提交 | Standard + 全边界 + 全回归 + 跨环境（不同分辨率/数据量） |

> 个人开发者时间有限，**默认 Standard**，核心链路或对外交付才上 Exhaustive。

---

## 修复循环（严格按序）

```
定位 → 最小修复 → 单个 commit → 前后对比证据 → 回归测试
```

1. **定位**：先稳定复现，确认根因（呼应工程方法论工具箱的「没找到根因不许动手」）。
2. **最小修复**：只改导致问题的那一点，不顺便重构。
3. **单个 commit**：一次修复一个 commit，便于回滚与追查（配合 `git-ship`）。
4. **前后对比证据**：同一操作，修复前截图/输出 vs 修复后截图/输出。**两者都要有**。
5. **回归测试**：确认这次修复没弄坏别的东西（跑相关测试 / 重跑主路径）。

---

## 证据要求（硬门槛）

- **修复前**：问题存在的证据（报错、错误截图、错误输出）。
- **修复后**：问题消失的证据（正常截图、通过输出）。
- **没有对比证据 = 验收不通过**，无论代码改得多合理。
- 对比证据可以是：两张截图、两段终端输出 diff、两个测试运行结果。

> 融合说明：gstack 原版要求「before/after evidence」作为 QA 验收的强制项，这里原样保留，
> 因为它正好是 AI 评审最容易造假的地方（编「已修复」），必须用真实证据封死。

---

## 自控机制（防止越修越乱）

1. **WTF-likelihood 停手线**：如果你改完之后，心里「这改动到底对不对我也不确定」的感觉
   **超过 20%**，立刻停下，回到定位步骤重新想——不要「先提交再说」。
2. **修复数量硬上限**：同一个问题，连续 **3 次修复还没好**，说明方向错了。
   不是再试第 4 种改法，而是回到根因重新分析（可能一开始定位就偏了）。
3. **不要顺手改别的东西**：修复循环里发现的其它问题，记下来另开，不混进当前 commit。

---

## 分类输出（每条验收结论都要归类）

| 标签 | 含义 | 何时用 |
|---|---|---|
| **verified** | 有前后对比证据，确认通过 | 修复前+后证据齐全 |
| **best-effort** | 尽力了但没有完整证据，需作者复核 | 环境限制拿不到对比（如偶现问题） |
| **reverted** | 修复引入更大问题，已回滚 | 改完更糟，退回上一版 |

输出示例：
```
[QA][Standard] 登录按钮点击无响应
- verified：修复前(点击无反应截图) → 修复后(跳转成功截图) at login.js:42
- 回归：重跑主路径 3 项通过
```
